# Служебная почта

Настройки: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`.
Пустой host отключает доставку, письма сохраняются в `web.outbox`. Порт 465 использует TLS сразу, остальные порты требуют STARTTLS. Проверка сертификата обязательна.

Для выбранного владельцем Gmail используется отдельный пароль приложения с названием `CRS-VPN-SMTP`, обычный пароль Google не нужен. Секреты задаются только в приватном окружении. После изменения Compose environment нужно пересоздать только API: `docker compose up -d --no-build --no-deps api`.

## Очередь в этой ветке

Миграция `0004_mail_delivery` добавляет попытки, срок следующей попытки, аренду записи и причину ошибки. Worker запускается вместе с API и проверяет очередь каждые 5 секунд. Обработчики запросов только записывают письма в БД.

- `FOR UPDATE SKIP LOCKED` и аренда на 5 минут защищают запись от одновременного захвата несколькими процессами.
- После сбоя отправка повторяется через 30 секунд, затем с удвоением задержки до часа, максимум 8 попыток.
- После перезапуска незавершенная запись снова доступна по истечении аренды.
- Использованные, просроченные ссылки и ссылки на замененный email не отправляются. Старые записи без хеша токена проверяются по ссылке своего домена.
- Один Message-ID сохраняется между попытками. При разрыве после принятия письма SMTP повторная доставка возможна; гарантии единственной доставки нет.
- В ошибках сохраняется только класс исключения, без текста письма, секретов и ответов провайдера.
- `sent_at` означает принятие SMTP-сервером, попадание во входящие проверяется отдельно.

У записей с `attempts >= 8` автоматические попытки прекращаются. Перед ручным повтором проверить причину и актуальность ссылки. Не отправлять старую очередь массово без проверки токенов.

## Проверка перед выпуском

1. Из контейнера API проверить TCP/TLS к выбранному SMTP.
2. Создать отдельный тестовый аккаунт на своем адресе с plus-суффиксом.
3. Проверить получение письма, подтверждение email, сброс пароля и отклонение повторно использованной ссылки.
4. Убедиться, что старый пароль больше не подходит и чужие аккаунты не изменены.
5. Удалить только созданные в этой проверке тестовые записи.

На действующем сайте до развертывания этой ветки остается прежний отправитель без автоматического повтора. Проверку нового worker не заменяет проверка текущего production.
