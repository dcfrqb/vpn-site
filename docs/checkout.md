# Покупка подписки на сайте

Google/email-аккаунту не нужен Telegram для оплаты и получения VPN. После выбора тарифа сайт сохраняет выбранный срок при входе, запрашивает цену у платежного API бота и показывает итог перед переходом в ЮKassa.

Браузер отправляет только код тарифа, срок, UUID попытки и ожидаемую цену. UUID аккаунта берется из серверного сеанса. Ключ магазина на сайт не передается. Возврат из ЮKassa открывает `/checkout/<UUID>`, где сайт проверяет статус своего заказа. Подписка, ссылки и история оплат доступны в кабинете без Telegram.

## Включение

Изменение требует совместимого платежного API бота с миграцией `r31_01_site_checkout`. До приемки владельцем checkout выключен по умолчанию.

- `SITE_CHECKOUT_ENABLED=true` включает каталог бота, заказы и профиль UUID-аккаунта.
- `BOT_API_URL` должен указывать на внутренний API бота, `BOT_API_TOKEN` должен совпадать с его внутренним токеном.
- Доступ сайта к панели необходим для реального кабинета, ссылки и устройств.
- Единственный webhook остается на боте. `YOOKASSA_API_KEY` в окружение сайта не добавлять.

Полный порядок развертывания, восстановления и событий возврата описан в `vpn-bot/docs/SITE_CHECKOUT.md`.

## Проверка

API-тесты проверяют принадлежность заказа сеансу, запрет подмены аккаунта и суммы, ошибки доступа, кабинет и удаление устройства без Telegram. Внутренний API отвечает только доверенному сайту; наружу его не публиковать.

Локальный симулятор бота позволяет пройти регистрацию, выбор тарифа, успешную оплату или отмену и кабинет без реального списания. Для web использовать development и `NEXT_PUBLIC_CHECKOUT_DEMO_ORIGIN=http://127.0.0.1:18050`. Этот переход разрешен только в development и только на явно указанный loopback origin.

Возвраты пользователь оформляет через поддержку; отдельной кнопки заявки на возврат на сайте пока нет. Перенос подписки, купленной без Telegram, в учет бота при последующей привязке Telegram не реализован.
